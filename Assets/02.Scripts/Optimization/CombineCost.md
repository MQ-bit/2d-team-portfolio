# 착탄·조합 부하: 동일 장판 마스크 공유

## 문제와 선택

하나의 잘린 장판 형상을 바닥과 VFX가 각각 표시하면서 동일한 픽셀 판정과 Texture2D 생성을 반복하는 비용을 줄인다. 형상 계산 자체, 벽 차집합, 콜라이더와 시각 효과 설정은 개별 마커로 구분한다.

| 고민 | 검토한 방법 | 선택과 이유 |
|---|---|---|
| 장판 마스크 생성 비용을 어떻게 줄일까? | A. 해상도 낮추기 / B. 동일한 형상의 결과 공유 | B. 해상도와 픽셀 판정 결과를 유지하며 중복 작업을 줄이기 위해서 |
| 공유 텍스처의 수명을 어떻게 관리할까? | A. 영구 캐시 / B. 참조 수 관리 | B. 마지막 사용자가 해제할 때 자원을 제거하여 캐시가 계속 쌓이지 않게 하기 위해서 |

## 두 버전

- 원본: `../Potion/Visual/PotionAreaMaskRenderer.cs`
- 개선: `OptimizedPotionAreaMaskRenderer.cs`
- 연결: `ComparisonAreaMaskRenderer.cs`
- 선택: `SharedMask`

`PotionAreaFootprint`는 생성 후 변경하지 않는 형상 데이터로 사용된다. 같은 footprint 객체를 참조하는 경우에만 공유하며, 동일해 보이는 다른 형상을 근사 비교하여 합치지 않는다. 해상도 256, RGBA32, 픽셀 판정식과 샘플링 설정은 원본과 동일하다.

## 확인된 에디터 결과

동시 조합 10쌍, 같은 시드 순서, 각 3회 실행 중앙값이다.

| 지표 | 원본 | 마스크 공유 |
|---|---:|---:|
| Mask.SetFootprint 전체 호출의 inclusive 시간 합계 ms/실행 | 561.709 | 356.325 |
| 같은 구간의 inclusive GC bytes/실행 | 5,439,060 | 3,316,692 |
| 조합 처리 최대 단일 호출 ms | 60.075 | 36.077 |

마스크 GC 합계는 각 버전의 3회에서 같은 값이었다. 시간은 변동이 있으므로 실행별 값도 결과 JSON에 보존한다. 구간 inclusive 시간은 서로 겹치므로 합산하지 않는다. 원본·개선 모두 실제 조합 수와 기능 판정을 함께 확인한다.

## 검증과 한계

- 실제 벽 클리핑으로 만든 형상에서 원본/개선 마스크를 GPU에서 읽어 픽셀별로 비교했다.
- 같은 형상 재연결 시 텍스처를 다시 만들지 않는지, 한 사용자 해제 후 다른 사용자의 텍스처가 유지되는지 확인했다.
- 마지막 사용자 해제 시 캐시 항목 제거와 null 형상의 클리핑 비활성화를 확인했다.
- 최초 마스크 생성 비용은 남아 있다. native 클리핑, 형상 생성 및 VFX의 모든 비용을 해결한 것은 아니다.
- GPU 실행 시간이나 드로우콜 감소를 입증한 작업이 아니다.
- 에디터 전체 프레임 최대값을 조합 함수에 전부 귀속하지 않는다. `event-frames.csv`는 같은 프레임의 비용을 연결하고, `observed-spikes.csv`는 무효/경계 프레임 진단에 사용한다.

로컬 근거: `Logs/Optimization/editor-core.json`, `editor-results.json`, 각 분석 보고서. 최종 빌드 결과는 `Docs/OptimizationResults.md`에 정리한다.
