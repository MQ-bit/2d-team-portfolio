# 적 탐색 비용: 조회 대상 레이어 제한

## 문제와 선택

원거리 적은 매 FixedUpdate에 주변 콜라이더를 조회하고 각 콜라이더의 부모에서 플레이어 수신자를 찾는다. 기존 코드는 결과 List를 이미 재사용하므로 새 배열 생성 제거를 개선 내용으로 제시하지 않는다.

| 고민 | 검토한 방법 | 선택과 이유 |
|---|---|---|
| 적이 많을 때 플레이어 탐색 비용을 어떻게 줄일까? | A. 탐색 주기 늘리기 / B. 대상 참조 캐시 / C. 물리 조회 대상 제한 | C. 감지 주기와 재획득 흐름을 유지하면서 불필요한 콜라이더 반환과 부모 컴포넌트 조회를 줄이기 위해서 |

## 두 버전

- 원본: `RangedEnemyController.FindPlayerInRange`의 기존 본문
- 개선: `OptimizedEnemySearch.Find`
- 선택: `EnemySearch`

데모의 단일 플레이어 생성 후 실제 자식 콜라이더의 레이어를 수집한다. 이름이 Player인 레이어만 하드코딩하지 않으며, 기존 탐색에 포함되던 트리거도 포함한다. 검색은 기존과 같은 FixedUpdate에서 수행하고, 결과 List 재사용과 TargetKind 확인을 유지한다.

## 검증과 측정

- 플레이어의 몸체와 별도 레이어의 센서가 함께 있는 조건에서 원본/개선 탐색 결과를 비교했다.
- 범위 안팎과 플레이어 비활성화 조건에서 같은 대상을 반환하는지 확인했다.
- 이동/정지 10·30·60명, 밀집 30명 조건을 제공한다.
- `Optimization.Enemy.FindPlayer`와 FixedUpdate의 호출당 시간, 프레임당 시간, 호출 수를 함께 비교한다.
- 실제 수치는 원본·개선의 유효한 캡처가 모두 확보된 환경에서만 전후 비교한다. 에디터에서 포커스 이탈로 실패한 실행은 성과 계산에 합치지 않는다.

## 적용 범위와 남은 조건

현재 개선은 단일 플레이어 및 콜라이더 레이어가 고정된 격리 데모에 적용한다. 해당 컨텍스트가 없으면 전체 필터 조회로 돌아간다. 다중 플레이어, 실행 중 레이어 변경, 콜라이더 추가가 있는 게임 경로에는 컨텍스트 갱신 계약을 먼저 마련해야 한다.

타겟 캐시와 탐색 간격 조절은 이번 개선에 포함하지 않았다. 감지 지연이나 대상 전환 규칙을 바꾸는 별도 실험으로 구분한다.
